# Connect Log 운영 기준

현재 로컬 소스 기준: 2026-09-06. 이 문서는 앱 화면에 안내 문구를 추가하지 않는다.
Apps Script 실사용 배포 버전 확인은 별도이며 `AGENTS.md`의 고정 경로를 따른다.

## 기본 흐름

1. 녹음 업로드 후 `정리본 생성·복사`를 누른다. 여러 파일은 순차 처리한다.
   일괄 정리본 생성 후 `5A ADMIN 일괄 적용`을 한 번 누르면 해당 묶음의
   미저장 정리본 전체를 각 학생·상담일의 ADMIN 특이사항에 저장한다.
2. 원문을 먼저 저장한 뒤 정리본을 만든다. 생성 실패 시 원문은 남으며,
   `정리본만 다시 생성`으로 재시도한다. 단일 녹음의 생성 완료와 ADMIN/Docs
   저장은 별개다. 일괄 작업은 ADMIN 저장이 확인돼야 저장 완료로 센다.
3. 현재 정리본을 ADMIN에 반영하거나, CSV 저장 흐름에서 자동 반영한다.
   CSV 버튼의 자동 ADMIN 반영은 현재 정리본의 반영 대상이 선택된 CSV 행에
   포함될 때만 실행된다. 모든 학생의 미저장 내용을 일괄 반영하는 기능은 아니다.
4. ADMIN의 내보내기 CSV를 업로드하거나 다운로드 감지로 불러온다.
   승인된 자동 전송 조건이 맞으면 저장을 시작하고, 아니면 기존 저장 버튼을 쓴다.
5. Docs 저장 결과를 확인한다. 일부 묶음이면 `이번 묶음 확인`, 해당 CSV 전체가
   끝났으면 `오늘 전체 완료 확인`을 누른다. 이 버튼을 누르기 전까지 결과 화면은
   새로고침 후에도 유지된다. ADMIN 자동 반영이 실패해도 Docs 처리는 계속될 수
   있으므로 한쪽 성공을 다른 쪽 성공으로 해석하지 않는다.

## 완료와 미완료

| 상황 | 최근 로그 목록 | 의미 / 확인할 곳 |
| --- | --- | --- |
| 모든 행 성공·중복·정상 제외 | 완료 | 처리가 끝났고 정상 결과로 확정됨 |
| 대기 행 없이 실패·확인 필요가 남음 | 미완료 | 처리 종료. Docs 저장 성공은 아직 미확정; CSV 결과 확인 |
| 대기 행이 남음 | 미완료 | 아직 처리할 행이 있음 |
| 처리 이력이 없음 | 미완료 · 기록 없음 | 이 앱의 로컬 이력에 해당 날짜 기록이 없음 |
| 저장 진행 중 | 대기 행이 있으면 미완료 | CSV 영역의 진행 건수·현재 단계 확인 |
| 중간에 종료 / 연결 중단 | 대기 행이 있으면 미완료 | CSV 영역의 중단 안내와 이어서 저장 확인 |

- 최근 로그 목록의 `저장 완료 N명`은 해당 수업 날짜의 저장이 확인된 학생 수다.
  기존 결과 로그와 현재 체크포인트를 합쳐 같은 학생 문서는 한 번만 센다.
  신규 저장, 기존 내용 교체, 이미 저장됨, 응답 지연 후 저장 확인은 포함한다.
  실패, 저장 미확정, 확인 필요, 제외는 인원에 포함하지 않는다.
- 상세 결과 CSV가 없으면 다운로드 원본의 파일 해시와 행 지문이 처리 이력과
  모두 일치할 때만 성공·중복 행의 학생 문서를 중복 제거해 인원을 복구한다.
  원본이나 학생 식별 근거도 없으면 `인원 확인 필요`로 표시한다. 처리 건수를
  학생 수로 대신 표시하거나, 집계를 복구하려고 Docs를 재전송하지 않는다.
- 상세 Docs 저장 결과 로그는 7일 보관한다. 하루 뒤 자동 정리되어 최근
  등원일 목록의 저장 인원 근거가 먼저 사라지지 않게 한다.
- CSV 작업의 `36/36건`은 처리 결과가 정해진 행 수/전체 행 수이며 인원과 별개다.
- 같은 CSV를 20명씩 나눠 처리하면 앞 묶음은 `이번 묶음 처리 완료 · 오늘 전체
  20/60건`처럼 표시한다. 남은 행은 미완료로 유지하며, 60명 모두 정상 처리된
  마지막 실행에서만 `오늘 전체 처리 완료 · 60/60건`을 표시한다.
  결과 화면에는 중복을 제거한 `저장 완료 N명`도 함께 표시한다.
- 이전 버전에서 첫 묶음 뒤 남은 대상이 `제외`로 잘못 저장된 동일 CSV는 다시
  열 때 현재 처리 가능한 행을 미처리로 복구해 이력을 저장한다.
- 날짜 목록은 한국 시간 기준 오늘부터 거꾸로 월·수·금·토·일 중 3개다.
  화·목에는 오늘 행을 억지로 만들지 않는다. 실제 달력상 오늘/어제만 그 문구를 쓴다.
- 날짜별 전체 완료 상태는 가장 최근 CSV 이력을 따른다. 완료 인원은 해당 날짜의
  모든 결과 로그에서 학생별로 중복을 제거해 계산한다.
- CSV 행의 날짜가 하나로 정해지면 그 날짜를 사용한다. 날짜가 섞였거나 판별되지
  않으면 시작 시각의 날짜로 대체될 수 있으므로 혼합 날짜 CSV는 해석에 주의한다.

## 버튼 기준

| CSV 상태 | 행 목록 | `선택한 기록을 학생 Docs에 추가` | 이어서 저장 |
| --- | --- | --- | --- |
| 파일 없음 | 숨김 | 비활성 | 숨김 |
| 이미 정상 완료한 동일 파일 | 숨김 | 비활성 | 숨김 |
| 새로운 처리 가능 행 선택됨 | 표시 | 활성 | 복구 가능한 작업이 있을 때만 |
| 선택 없음 / URL 미설정 / 이력 읽기 실패 | 필요 시 표시 | 비활성 | 조건에 따라 숨김 또는 비활성 |
| 저장 중 | 처리 화면 | 숨김 | 숨김 |

완료 파일에서 새 파일로 바꿀 때 이전 완료 상태 때문에 새 저장 버튼을 숨기면 안 된다.
각 실행 결과 화면은 `이번 묶음 확인` 또는 `오늘 전체 완료 확인` 전까지 유지하고,
확인 시각은 체크포인트에 저장한다. 중간 묶음을 확인하면 남은 행 목록과 저장 버튼으로
돌아가고, 오늘 전체 완료를 확인하면 행 목록 없이 비활성 저장 버튼만 남는다.
완료 CSV에서도 `Docs 저장 다시 확인`을 누를 수 있다. 실제 문서에 현재 본문이
있는지 verify-only로 읽기만 하며, 명확히 없다는 응답을 받은 항목만 실패로 바꿔
기존 재시도 경로를 연다. 통신 오류나 불명확한 응답은 확인 필요로 남기고 자동
재전송하지 않는다. 재확인 결과를 새 체크포인트에 먼저 저장하므로 이전 성공
체크포인트가 누락 확인 결과를 다시 완료로 덮어쓰지 않는다. 원래 결과 CSV는 보존한다.
`확인 필요`는 정상 완료 파일과 동일한 자동 재전송 제외 조건으로 취급하지 않는다.
저장 여부가 불확실한 항목은 Docs 확인 후 재시도하며, 성공 여부를 추정해 재전송하지 않는다.

## 새로고침과 재실행

| 대상 | 유지 / 복구 기준 |
| --- | --- |
| CSV 처리 이력 | 로컬 파일에 유지. 새로고침·재실행 후에도 날짜별 목록 복구 |
| 진행 중 CSV | 브라우저 새로고침/연결 해제와 별개로 앱 프로세스의 작업 스레드가 순차 저장. 앱 프로세스 종료 후에는 체크포인트에서 복구 |
| 녹음 일괄 목록 | 미저장 정리본·미확인 완료 화면 유지. 모든 ADMIN 저장이 확인되고 `일괄 저장 완료 확인` 후 새 세션 초기화 때 정리 |
| 중단·실패·확인 필요 녹음 일괄 작업 | 상태와 파일 경로를 점검한 뒤 복구 대상으로 유지 |
| 입력·원문 초안 | 저장된 초안에서 학생·작성자·원문/경로 등을 복구할 수 있음. 상담일은 오늘로 설정 |
| 저장된 원문·정리본·기존 CSV 결과 | 새로고침만으로 삭제하지 않음. 미확인 CSV 결과 화면은 해당 확인 버튼을 누르기 전까지 복구 |

파일 선택 위젯이 비어 보이는 것과 디스크의 초안/처리 이력이 사라지는 것은 다르다.
CSV 이력은 이 설치의 로컬 기록이며, 다른 PC와 자동 공유되는 전역 기록이 아니다.

## 녹음 일괄 ADMIN 저장

- 정리본은 일괄 처리 현황에서 이전·다음 화살표 또는 학생 선택으로 확인한다.
  수정 내용은 해당 파일에 보존하며 수정한 파일만 다시 저장 대기가 된다.
  해당 일괄 정리본의 개별 ADMIN 저장 버튼은 별도로 표시하지 않는다.
- 각 파일의 학생명·상담일을 사용한다. 현재 입력칸의 학생명이나 다른 학생의
  마지막 선택 SID는 사용하지 않는다. 저장 대상은 기존 매핑·사용자 선택·명단
  대조로 확정하며, 동명이인 후보를 확정할 수 없으면 해당 학생만 보류한다.
- 생성된 정리본과 저장 확인 대기 상태를 먼저 기록한 뒤 기존 ADMIN 동기화
  경로로 저장한다. 기존 내용 백업·동시 변경 보호·동일 내용 중복 방지를 유지한다.
- `ADMIN 저장 완료 N명`은 확인된 SID를 중복 없이 센다. 같은 학생 녹음이
  여러 개라도 한 명이다. 생성 완료만 된 학생이나 실패·확인 필요는 포함하지 않는다.
- `5A ADMIN 일괄 적용`은 미저장 정리본만 저장한다. 저장 실패 재시도는 원문
  추출·정리본 생성을 반복하지 않는다. 응답 지연 후 재시도도 기존 내용부터 확인한다.
- 일괄 목록은 저장 확인 전 삭제하지 않는다. 전체 저장 확인 후에만
  `일괄 저장 완료`와 확인 버튼을 표시한다. 이 흐름은 Google Docs 자동 저장이 아니다.

## CSV 장시간 저장과 복구

- 저장은 Streamlit 화면 재실행과 분리한다. 탭 새로고침/닫기는 전송을 취소하지
  않지만, 앱 프로세스 종료·PC 종료·절전 중에는 계속 진행됨을 보장하지 않는다.
- OS 파일 잠금으로 이 설치에서 한 작업만 전송한다. 다른 탭은 같은 체크포인트의
  진행 상태를 표시한다. 경과 시간만 보고 실행 중인 작업을 죽은 것으로 판단하지 않는다.
- 각 전송 직전에 요청을 체크포인트에 기록하고, 응답 뒤 결과를 저장한 다음 다음 행으로
  넘어간다. 체크포인트/처리 이력 쓰기 실패 시 남은 전송을 멈춘다.
- JSON은 같은 폴더의 고유 임시 파일에 기록하고 flush/fsync 후 원자적으로 교체한다.
  일시적인 Windows 파일 잠금은 제한적으로 재시도하며 기존 정상 파일을 먼저 지우지 않는다.
- 앱 종료 직전 전송 결과가 불확실하면 이어서 저장 시 해당 요청을 verify-only로 확인한다.
  확인되지 않아도 즉시 같은 요청을 다시 쓰지 않고 확인 필요 결과로 남긴다.
- 체크포인트에 저장된 확정 결과로 처리 이력을 복구할 수 있다. 수동 업로드 파일은
  프로세스 재실행 후 다시 선택해야 할 수 있다. 다운로드 경로는 기존 복구 조건을 따른다.
- 영구 처리 이력에는 원문을 추가하지 않는다. 진행 체크포인트에는 정확한 저장 여부를
  확인하기 위한 요청 본문 최대 다섯 건이 잠시 포함될 수 있고 각 결과 확정 시 제거된다.
- 서로 다른 학생 문서는 최대 다섯 건씩 병렬 전송하며 같은 학생 문서의 기록 순서는
  유지한다. 응답이 완료된 자리를 다음 학생으로 채우므로 한 문서의 느린 응답 때문에
  나머지 전송이 묶여 기다리지 않는다. 타임아웃 뒤 verify-only 확인도 해당 작업
  스레드에서 처리한다. 확인 중인 문서에는 다음 쓰기를 보내지 않는다.
  기존 batch 휴식, 타임아웃 확인, 같은 날짜 교체 정책도 유지한다.
  결과 CSV 저장 실패도 중단 원인으로 남기며 성공으로 숨기지 않는다.
- Apps Script는 짧은 전역 보호 구간에서 문서별 임대를 얻고 실제 문서 작업은 서로 다른
  문서끼리 병렬 처리한다. 로컬 원본 변경은 배포 전까지 운영 Web App에 적용되지 않는다.
- Apps Script는 한 요청에서 찾은 상담 표 헤더를 중복 확인과 새 행 준비에 재사용한다.
  이전 형식의 헤더도 한 번의 탐색으로 판별하며, 뒤에 있는 우선 헤더의 선택 규칙은
  유지한다. 요청 간 또는 문서 간 캐시는 사용하지 않는다. 읽기 전용 GET의
  `server_revision`으로 배포된 코드 개정을 확인할 수 있다.

검사: `scripts/check_csv_persistence.py`, `scripts/check_csv_worker.py`,
`scripts/check_google_docs_parallel.py`.
격리된 임시 파일과 가짜 Docs 응답으로 재실행·중복 시작·응답 후 중단·디스크 실패를
검사한다. 실제 Docs 쓰기, 전원 차단, 절전 복구를 검증했다는 의미는 아니다.

## 중복과 날짜 교체

- 대상 학생 문서의 같은 날짜 + 같은 내용: 중복으로 보고 추가하지 않는다.
- 같은 날짜 + 바뀐 내용/포맷/진도: 해당 날짜의 기존 내용 칸을 새 내용으로 교체한다.
- 날짜가 다름: 내용이 같아도 새 날짜 기록으로 저장한다.
- Apps Script의 내용 비교는 줄바꿈 통일과 양끝 공백 제거 후 비교다.
  의미가 비슷하다는 이유로 임의로 중복 처리하지 않는다.
- 같은 날짜 행이 이미 여러 개라면 동일 내용이 있는지 먼저 확인하며,
  교체할 때는 마지막으로 일치하는 날짜 행을 사용한다. 연강/과목별 구분 키는 아니다.

## 진단과 배포

2026-10-01 Docs 속도 최적화 배포: 기존 운영 배포의 버전 22에
`docs-speed-20261001`을 반영했다. 배포 ID·URL·실행 계정·공개 범위는 유지했다.
읽기 전용 GET은 HTTP 200과 해당 `server_revision`을 반환했다. 원본 문법 검사,
날짜 정책·헤더 재사용·확인 요청 회귀 검사와 앱 빠른 검사 9개를 통과했다.
실제 학생 Docs POST와 60명 저장 시간 측정은 실행하지 않았다.

- 화면 기준: `DESIGN.md`, 격리 검사: `docs/UI_BASELINE.md`.
- 빠른 검사: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check_quick.ps1`.
- 오류가 나면 원문과 처리 이력을 보존하고 실패 단계부터 확인한다.
- 실사용 ADMIN/Docs 쓰기, Apps Script 배포, ZIP 생성은 별도 요청이 있을 때만 한다.
